# 3m-ui 接入、部署与管理

依据 [3m-ui v1.4.1](https://github.com/kazeyukiro/3m-ui/tree/v1.4.1)（`cab27bd78923ea3cea7eb1cdfd5687d4719983bf`）的 Go 路由、请求模型、配置加载器和官方安装脚本实现。3m-ui 使用 Mihomo 与 `/api/v1` JWT 接口，和 3x-ui 的 Xray、Cookie/CSRF 接口分别适配。

`contracts/3m-operations.json` 收录 171 项操作，包含 `/nodes` 与 `/listeners` 别名。这个数字表示已登记的接口，不表示每项操作、所有参数组合或所有第三方联动已逐项实测。常用功能提供表单，复杂功能使用真实 API 的参数/JSON 编辑器；不是原面板每个专用页面的复制。

## 接入与新部署

- 输入 SSH 信息即可发现原生、systemd、Docker 实例，同一服务器可同时管理两类面板。配置无法读取的实例保留错误说明，不能把它当成未安装并覆盖。
- 接入保留原账号、节点、订阅和服务配置。首页只读 SQLite（包括 WAL），不解密用户凭据；分享由认证后的面板生成。监听端口范围保留在说明和管理配置中。
- 管理使用现有管理员账号、可选 TOTP 或登录 JWT；订阅访问 token 不能用于管理。会话只在内存中保留。首次登录必须改密时，仅开放账号查询和改密，不能绕过上游限制。
- 默认新部署为 3x-ui v3.10.0，可改选 3m-ui v1.4.1。两者均创建 VLESS + REALITY 节点；3m-ui 自动创建 Listener、用户和绑定，应用配置后检查核心与端口。
- 3m-ui 使用经 SHA-256 校验的官方安装脚本，通过 `5a-ui-install.service` 后台运行，管理资料保存在目标服务器的 `/var/lib/5a-ui/`。安装未完成时可继续原产品的安装，不允许把失败记录切换为另一产品。发现外部实例时优先接入。
- 3m-ui 首次启动即通过环境覆盖绑定 `127.0.0.1`，独立订阅端口关闭。默认配置不额外开放管理端口。若主动改变这些绑定，需要同步调整服务器的 `3m-panel.env`；环境变量优先于面板配置。节点分享可直接导入客户端；公网订阅需要自行配置有效域名和入口。

## 功能与实际覆盖

| 范围 | 实现 | v1.4.1 隔离环境验证 |
| --- | --- | --- |
| 认证与多实例 | 自动读取连接信息、手动入口、JWT/TOTP、首次改密、准确实例目标 | 已有原生两类面板只读发现；Docker/原生测试面板登录、改密、会话复用；HTTPS/SNI |
| Listener | 增改删、启停、端口字符串/范围、协议、传输、TLS/REALITY、模板和版本高级接口 | 增改删启停、重复拒绝、配置保存回读、REALITY 节点真实代理握手 HTTP 200 |
| 用户 | 增改删、启停、流量配额、到期、关联 Listener | 配额、期限、绑定、启停回读；已有密码/UUID 不会被掩码响应覆盖 |
| 分享与订阅 | 原面板生成链接/订阅、二维码、复制、导出与完整客户端配置 | 节点分享、用户订阅读取；浏览器合成数据二维码展示 |
| 配置、出站、路由、DNS | 保留完整视觉配置/JSON，生成、校验、应用；“应用并检查 Mihomo”回读核心 | 完整配置保存回读、生成/校验/应用、错误配置拒绝；运行状态读取 |
| 状态、流量与日志 | 仪表盘、连接、规则、代理组、日志、流量 API | 真实状态、流量、连接、规则、代理组、日志读取 |
| 面板与安全设置 | 常用设置及完整 JSON；TLS、账号/TOTP、订阅、token 等高级操作 | 设置保存回读、手动自签名 HTTPS 启用后自动识别并重新连接 |
| 备份恢复 | ZIP 下载、`database` multipart 导入、准确重启、恢复后重新认证 | 备份→删除对象→恢复→重新认证→对象回读 |
| 实例与核心服务 | 所选 systemd/Docker 生命周期，Mihomo 启停/重启 | Docker 与原生重启、核心停止/启动/重启及回读 |
| 核心版本 | 版本列表、异步切换、任务查询、回滚 API | 原生隔离实例实际切换版本、核对任务 ID/成功状态、回滚并确认核心运行 |
| 面板版本 | 原生标准服务的官方稳定/预发布更新；升级后重新接入核对 | 原生稳定通道 v1.4.1 同版本更新完成，官方任务就绪、账号复用和 Listener 保留；未测试跨版本迁移 |
| 集群、Telegram、ACME 等 | 已登记的真实接口与参数/JSON 编辑；不可用操作显示原因 | 未配置外部账户、未发送消息、未申请公网证书；未验收所有拓扑与联动 |

## 失败处理与兼容边界

- 管理基线为 v1.4.1；更旧版本保留只读状态。未来版本按已审计目录请求，缺少或变化的接口返回明确错误，未宣称所有未来版本兼容。
- 常用编辑带回读摘要，保存前检测其他会话修改；上游无原子 CAS，因此仍有检查与写入之间的竞争窗口。失败/超时不自动重放写入，需要先回读确认。
- 3m-ui 数据保存与 Mihomo 配置应用是不同步骤。保存成功不等于核心已运行或所有节点可连接；应执行应用检查并按实际协议验证。已运行核心不会被一键安装重复启动。
- 恢复是完整实例恢复，不支持保留主机设置。最多导入/导出 2 MiB；更大备份使用原面板。恢复后账号和监听参数可能变化，需要重新认证。连接数据库在调用恢复前关闭，避免旧 WAL 影响恢复。
- 面板自升级只开放标准原生 `3m-ui.service`，Docker、自定义服务与共享程序受保护，应使用原部署方式升级。共享 Mihomo 程序不能为一个实例独立切换版本。无可识别服务管理器的进程不提供安全自动重启。
- 集群的通用 `/cluster/{id}/proxy` 不开放，因为它可绕过操作目录的读写限制；可使用明确的集群接口或直接 SSH 接入目标服务器。
- 第三方联动、所有协议/传输组合、所有高级操作和所有发行版没有逐项验收。Android/iOS/Windows/Linux 本轮设备交互、云平台发布也未完成，不能宣称与原面板的全部使用场景完全等价。

重建目录：`python3 tool/import_3m_api.py <外部上游检出目录>`，再运行 `fvm dart run tool/generate.dart`。导入工具使用 Go 注册路由作为接口依据，修正上游 OpenAPI 文档的路径布局，并补齐 DTO/handler 请求结构；开发机需要 PyYAML，目标 SSH 服务器不需要该依赖。项目内测试与文档只使用合成数据。
